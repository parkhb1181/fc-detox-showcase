# 2. 페이지뷰를 어떻게 셀지 정해야 했다

## 상황

Vercel Analytics에서 페이지뷰가 272만으로 잡혔습니다. 방문자 수를 생각하면 나올 수 없는 숫자였고, 확인해보니 버튼을 누를 때마다 주소가 바뀌면서 같은 방문이 여러 번 세지고 있었습니다.
방문자 수에는 영향이 없는 페이지뷰 한정 문제였지만, 이걸 계기로 GA4를 따로 붙여 참여 지표를 분리했습니다.

GA4를 붙이면서 부딪힌 문제는 **Next.js App Router에서 페이지뷰를 어떻게 셀 것인가**였습니다.

## 판단

- App Router의 화면 이동은 실제 문서 로드가 아니라서 gtag가 자동으로 잡지 못합니다.
- GA4의 "향상된 측정"이 history 이벤트로 잡아주긴 하지만, **GA 콘솔 설정에 따라 조용히 집계가 바뀝니다.** 코드로 확정하는 편이 재현 가능하다고 봤습니다.
- 자동 전송을 켜둔 채 코드에서도 보내면 **첫 진입이 두 번 셉니다.** 그래서 자동 전송을 끄고 첫 진입까지 전부 코드에서 보냅니다.
- 쿼리스트링까지 넣으려면 `useSearchParams`가 필요한데, 쓰는 순간 이 컴포넌트를 감싼 트리가 클라이언트 렌더링으로 내려가 **정적으로 미리 만들어둔 상품 페이지 445개가 깨집니다.** 쿼리스트링을 포기했습니다.

## 코드

`components/AnalyticsInit.jsx`

```jsx
/**
 * GA4 페이지뷰는 수동으로 보낸다 (config에서 send_page_view:false).
 *
 *   App Router의 클라이언트 내비게이션은 실제 문서 로드가 아니라서 gtag가 자동으로 못 잡는다.
 *   GA4의 "향상된 측정"이 history 이벤트로 잡아 주기는 하지만, 그건 GA 콘솔 설정에 의존해서
 *   껐다 켜지면 조용히 집계가 바뀐다. 코드로 확정하는 편이 재현 가능하다.
 *
 *   send_page_view를 기본(true)으로 두고 여기서도 보내면 최초 진입이 이중 집계된다.
 *   그래서 config에서 끄고, 최초 진입 포함 전부 이 훅이 보낸다.
 *
 *   useSearchParams를 쓰지 말 것. 그걸 쓰면 이 컴포넌트를 감싼 트리가 CSR로 내려가
 *   /open/* 445페이지 정적 프리렌더가 통째로 깨진다.
 *   쿼리스트링은 페이지뷰 URL에서 빠지지만 그 대가가 훨씬 크다.
 */
useEffect(() => {
  if (!GA_ID || typeof window === 'undefined' || typeof window.gtag !== 'function') return;
  window.gtag('event', 'page_view', {
    page_path: pathname,
    page_location: window.location.href,
    page_title: document.title,
  });
}, [pathname]);
```

분석 도구 키는 전부 환경변수로 주입하고, 없으면 조용히 비활성화되게 해서 로컬에서도 안전하게 돌아갑니다.

## 설명할 수 있는 것

- **왜 콘솔 설정 대신 코드인가**: 설정은 누가 언제 바꿨는지 추적이 안 되고, 코드는 커밋으로 남는다
- **이중 집계가 생기는 조건**: 자동 전송과 수동 전송이 첫 진입에서 겹칠 때
- **트레이드오프**: 쿼리스트링 정보를 잃는 대신 정적 프리렌더 445페이지를 지킴. 검색 유입이 35%인 서비스라 정적 페이지가 더 중요했음
